# CQA Local — Conversation Quality Analytics

Локальная копия прототипа Freedom Broker: оценка работы оператора выполняется моделью Ollama на этом компьютере. Транскрипты не отправляются в Gemini, OpenAI, ChatGPT, Claude или другой облачный сервис.

- **Чек-лист — это конфигурация**, а не код: `config/checklist.default.json` (8 критериев из PDF) редактируется в интерфейсе, каждое сохранение — новая версия.
- **Промпт генерируется из чек-листа.** Новый критерий начинает оцениваться без изменения кода.
- **Баллы считает код**, а не модель: шкалы → вес, перераспределение веса N/A до 100, округление до 2 знаков, секции, грубая ошибка отдельно. Покрыто юнит-тестами (включая пример «03 = N/A, 04 = 15 → 18,75»).
- **Ответ модели проверяется кодом**: допустимые значения, N/A только где разрешён, номера реплик в диапазоне, доказательство или проверенный участок для «Нет». При ошибке — до 2 автоматических исправлений.

## Запуск

Нужен только **Node.js 20+** (зависимостей нет, `npm install` не требуется).

```bash
git clone https://github.com/diyarseri/cqa-hackathon-local.git
cd cqa-hackathon-local
cp .env.example .env
```

1. Установите [Ollama](https://ollama.com/download) и загрузите локальную модель:

```bash
ollama pull qwen2.5:7b
```

2. В `.env` оставьте локальные настройки из `.env.example`. При необходимости добавьте `CQA_API_URL` организаторов для загрузки исходного набора. Эта ссылка используется только для получения данных; оценка выполняется локально.

3. Проверьте защиту и наличие модели, затем запустите приложение:

```bash
npm run local:check
npm start
```

Откройте http://127.0.0.1:8080. Сервер специально слушает только локальный адрес.

```bash
npm test
```

> За корпоративным прокси Node не использует `HTTPS_PROXY` сам по себе: запускайте `NODE_USE_ENV_PROXY=1 npm start` (Node ≥ 22.21).

## Как пользоваться

| Вкладка | Что делает |
|---|---|
| **Все диалоги** | Список набора с итогами, флагами грубых ошибок и открытыми апелляциями; фильтры; карточка диалога. **Загрузить разговор** (в «Дополнительные фильтры и действия») — свой транскрипт: формат API организаторов, одна запись или просто массив реплик `{timestamp, speaker, text}`; попадает в отдельный локальный набор. |
| Карточка | Транскрипт с номерами реплик; плеер для звонков (клик по времени — воспроизведение с этого места); результат по секциям и критериям; клик по доказательству прокручивает к реплике, подсвечивает её и перематывает запись; «проверено #a–#b» — участок, где ожидалось пропущенное действие; кнопки «Проверить ещё раз», «Промпт», «Оспорить». |
| **Проверить набор** | Оценка всего `group_id` с прогрессом, параллельностью, автоповтором (2→4→8 с), «Повторить ошибки», CSV. |
| **Критерии оценки** | Создание, редактирование, удаление, порядок критериев, шкалы, N/A и условие, пояснения для оценщика, история версий и восстановление. |
| **Спорные оценки** | Рабочее место проверяющего: спорная оценка, комментарий, фрагмент; подтвердить или изменить с причиной → пересчёт итога. |
| **Проверка точности** | Слепая ручная разметка и согласие человек/модель по каждому критерию. |
| **Результаты** | Где операторы теряют баллы: доля потерь по критериям, языкам и каналам, грубые ошибки, худшие диалоги. |
| ⚑ Проверка | Код сверяет цитаты с репликами и помечает сомнительные ответы модели для проверки человеком. |
| Экспорт / импорт | Один файл с набором, оценками, апелляциями, разметкой и чек-листами — для обмена между ноутбуками и демо без интернета. |

**Контрольный набор (23 ч):** в правом верхнем углу «Набор» → «+ добавить набор…» → ввести значение от организаторов → «Проверить набор» → «Начать проверку».

## Локальная модель и конфиденциальность

| | |
|---|---|
| Провайдер | Ollama на текущем компьютере |
| API модели | `http://127.0.0.1:11434/api/chat` |
| Модель по умолчанию | `qwen2.5:7b` |
| Прогонов на диалог | `EVAL_RUNS=1` |
| Стоимость API | $0; используется электричество и ресурсы ноутбука |
| Облачные модели | Заблокированы программно |

`server/lib/llm.js` принимает только loopback-адреса `127.x.x.x`, `localhost` и `::1`. Попытка указать внешний адрес или `LLM_PROVIDER=gemini/openai` завершится ошибкой до отправки транскрипта. Запрос к Ollama не содержит ключей авторизации. `/api/model` показывает `local_only: true` и `transcript_leaves_device: false`.

Для ноутбука с 16 GB RAM и RTX 4050 рекомендуется начать с `qwen2.5:7b` и одного прогона. Длинный диалог может обрабатываться несколько минут. Качество локальной модели нужно измерить во вкладке «Проверка точности» на ручной разметке команды.

Текущий чек-лист оценивается по транскрипту. Если позднее добавить критерии, требующие анализа аудиофайла, текстовая локальная модель вернёт явную ошибку вместо отправки записи во внешний сервис.

## Правила интерпретации чек-листа

Решения по спорным местам записаны **в самом чек-листе** (поле «Пояснения для оценщика» и «Общие правила»), попадают в промпт и меняются в редакторе без кода. Текущая версия — v3, уточнена по ручной разметке (см. «Точность»):

1. **01** Представиться = назвать имя; компания не обязательна; «[Имя скрыто]» считается именем; «Привет»/«Сәлем» без имени — «Нет».
2. **02** Переспрашивание того, что клиент уже написал боту, — «Нет».
3. **03** Раскрытие данных о конкретном счёте без идентификации — «Нет» **и** грубая ошибка. Клиент отказался от идентификации, ничего не раскрыто — «Да». Запрос по ходу диалога стал требовать идентификации (удаление счёта и т.п.), а проверки не было — «Нет».
4. **05** Спокойный клиент — достаточно вежливости. Если клиент указал на ошибку оператора, исправление ответа — реакция на проблему; «Нет» — только за пренебрежительный ответ («Ну, тогда сайт»). «Вы вообще читать умеете?» — оскорбление (грубая ошибка).
5. **06** Клиенту пришлось переспрашивать из-за расплывчатого или неверного ответа — не выше 4. Порог первой реакции 3 минуты считается от сообщения об эскалации; время вычисляет код.
6. **07** Прощание после того, как клиент подтвердил решение («Нашла, спасибо»), — «Да»; нет прощания, оператор закрыл чат или оставил последний вопрос без ответа — «Нет»; клиент ушёл / связь прервалась — N/A.
7. **08** Грубая ошибка не меняет балл, отмечается отдельно.
8. Ошибки распознавания речи в звонках не штрафуются; реплики во время удержания — внутренний разговор, только контекст.

## Точность

Результаты облачной Gemini из исходного проекта нельзя выдавать за точность локальной модели. После установки Ollama выполните слепую ручную разметку контрольных диалогов во вкладке «Проверка точности» и покажите жюри фактическое согласие человек/локальная модель.

## Архитектура

```
server/          Node.js без зависимостей (node:http)
  server.js      REST API + статика
  lib/datasource.js  адаптер API организаторов (без CORS), кэш, ссылки на записи
  lib/checklists.js  версии чек-листов (каждое сохранение — новая версия)
  lib/facts.js       факты, вычисляемые кодом (время реакции, удержание, уход клиента…)
  lib/prompt.js      генерация промпта из чек-листа
  lib/llm.js         локальная Ollama + блокировка внешних адресов
  lib/evaluator.js   вызов модели, проверка JSON, исправления, сохранение
  lib/appeals.js     апелляции и пересчёт
  lib/batch.js       пакетная оценка с ретраями
  lib/validation.js  ручная разметка и согласие
shared/          чистые модули, общие для сервера и браузера
  normalize.js   MM:SS и ISO 8601 → смещение в секундах, позиция в записи
  checklist.js   схема и валидация чек-листа
  scoring.js     расчёт баллов
web/             интерфейс: HTML + CSS + ES-модули без сборки
config/          начальный чек-лист из PDF
test/            node:test
data/            (не в git) кэш наборов, чек-листы, оценки, апелляции, разметка
```

**Dynamics 365.** Интерфейс монтируется в один корневой элемент `#cqa-app`, стили изолированы под `.cqa`, а все обращения к серверу идут через `web/js/api.js` (`window.CQA_API_BASE`). Для HTML web resource достаточно загрузить `web/` как ресурсы и указать адрес сервиса оценки. Хранилище (`server/lib/store.js`) можно заменить на таблицы Dataverse.

**Звонки.** Время в записи = время реплики − начало записи − паузы записи («приостановлены/возобновлены»); удержание остаётся в записи. Проверено на 5 звонках DEV (точность ~1 с). `audio_url` отдаёт HTML-страницу плеера, сервер извлекает из неё подписанную ссылку на MP3 (живёт ~1 час) и перенаправляет плеер.
