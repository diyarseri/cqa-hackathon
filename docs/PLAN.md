# План команды до финала

Этот файл — общий для нас обоих. Всё, что меняется, появляется здесь после `git pull`.

## Как мы делимся

| Что | Как |
|---|---|
| Код, инструкции, сценарий | GitHub: `git pull` в папке проекта, затем перезапуск `npm start` |
| Оценки, апелляции, разметка | **«Проверить набор» → «Дополнительные настройки» → Сохранить полную копию** → файл в Telegram → у напарника **Загрузить резервную копию**. Более новые данные побеждают, ничего не теряется. |
| API-ключ Gemini | Только лично (Telegram). **Никогда** не в репозиторий и не в чат с ИИ. |

Данные (`data/`) не попадают в GitHub — у каждого ноутбука своя папка. Перед демо обменяйтесь экспортом, чтобы у обоих было одно и то же.

## Почему мы можем выиграть

ML-специалисты не получают здесь преимущества: размеченных данных нет, обучать нечего, все используют LLM + промпт. Решает:
1. **Доверие к оценке** — у нас баллы считает код, каждая оценка ссылается на реплики, цитаты проверяются, сомнительные ответы помечены ⚑.
2. **Измеренная точность** — согласие с нашей ручной разметкой по каждому критерию и его улучшение через правку чек-листа (без кода).
3. **Польза для QA-отдела** — аналитика «где операторы теряют баллы», апелляции, версии чек-листов.
4. **Безупречная демонстрация** и контрольная точка в 23 ч.

## Шаги

### 1. Оплата модели (сейчас, 10 мин)
aistudio.google.com → API keys → проект ключа → **Set up billing**. Поставить бюджетное оповещение $10. Весь DEV стоит ≈ $0,80.

### 2. Установка — каждый на своём ноутбуке (30 мин)
1. Установить **Node.js LTS** (nodejs.org) и **Git** (git-scm.com). Перезапустить PowerShell.
2. `git clone https://github.com/nurssat/cqa-hackathon.git` → `cd cqa-hackathon`
3. `copy .env.example .env` → `notepad .env`:
   - `CQA_API_URL` — ссылка кнопки «Открыть GET для DEV» (стр. 3 задания, правый клик → копировать ссылку);
   - `GEMINI_API_KEY` — ключ;
   - `GEMINI_FALLBACK_MODELS=` — оставить пустым (все оценки делает одна модель).
4. `npm start` → открыть http://localhost:8080 — 65 диалогов.

### 3. Чистый прогон DEV — один ноутбук (15–20 мин)
«Проверить набор» → «Дополнительные настройки» → снять «Проверять только новые диалоги» → **Начать проверку** → при ошибках «Повторить неудачные».
Проверить фильтр «Грубые ошибки»: ожидаем 8 — ru-009, ru-022, ru-023, ru-029, kz-013, kz-015, en-013, en-014.
Затем **Сохранить полную копию** → отправить файл напарнику → **Загрузить резервную копию** у него.

### 4. Ручная разметка — вместе, 1–1,5 ч
1. Оба читаем чек-лист (3 стр.) и раздел «Правила интерпретации» в README — 10 минут.
2. Меню **Проверка точности**. Сначала **вместе** размечаем 2 диалога, обсуждая вслух — так договариваемся о правилах.
3. Затем каждый размечает 4 своих, не глядя на оценку модели.
4. Скриншот таблицы согласия. Критерии ниже 70% — расхождения отправить в чат с ИИ для настройки пояснений → повторный прогон → новое число («было 78%, стало 91%»).

### 5. Тест новых функций (по мере появления)
`git pull` → перезапуск `npm start` → прокликать → всё непонятное или сломанное — в чат.

### 6. Сон по очереди
Каждый спит 4–5 часов, пока второй тестирует. Уставший докладчик теряет больше баллов, чем недоделанная функция.

### 7. Репетиция (до 22 ч) — `docs/DEMO.md`
Три прогона с таймером, вместе. Отдельно: замена критерия быстрее 60 секунд.

### 8. Контрольная точка — 23 ч
1. Получить контрольный `group_id`.
2. Справа вверху «Набор» → «+ добавить набор…».
3. «Проверить набор» → **Начать проверку** → «Повторить неудачные», если нужно.
4. Если просят заменить критерий: меню «Критерии оценки» → правка → «Сохранить как новую версию» → «Проверить набор» → «Начать проверку» снова (новая версия переоценит всё).
5. **Сохранить полную копию** на оба ноутбука (резерв на случай сбоя сети).

### 9. 24 ч
Ссылка на репозиторий организаторам до стоп-кода. Выступление по `docs/DEMO.md`; вкладки браузера открыты заранее.

## Вопросы жюри — короткие ответы

| Вопрос | Ответ |
|---|---|
| Что если ИИ галлюцинирует? | Каждый вывод ссылается на реплики; цитаты сверяются кодом; баллы и итог считает код; сомнительные ответы помечены ⚑ для проверяющего. |
| Насколько точно? | Грубые ошибки — 8 из 8. Согласие с нашей ручной разметкой — 85% (34 из 40 ответов). Три независимых прогона и голосование убирают случайные ошибки модели. |
| Сколько стоит? | ≈ 3,5 цента за диалог при трёх прогонах (1,2 цента при одном); 10 000 чатов в день ≈ $120–350. |
| Казахский? | Один чек-лист для RU/KZ/EN; модель читает оригинал, объяснения по-русски. |
| Как добавить критерий? | В редакторе. Промпт генерируется из конфигурации — код не меняется. (Показать.) |
| Почему балл не считает модель? | Модель плохо считает; правила перераспределения N/A и округления — детерминированный код с тестами. |
| Dynamics 365? | Интерфейс — чистый HTML/JS в одном контейнере, адрес сервиса в одном файле; встраивается как веб-ресурс. |
| Персональные данные? | Данные хранятся локально, в модель уходит только транскрипт, уже замаскированный организаторами. |
